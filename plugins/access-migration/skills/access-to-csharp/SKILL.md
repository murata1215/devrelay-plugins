# Access → C# 移植規約

`access-export-reading` skill で読んだ export ソースを前提に、C# への移植を設計するための対応表と
成果物テンプレです。この skill は read-only の設計支援であり、コード生成の自動実行や
Access への書き戻しは行いません。

## 1. 対応表

| Access | C# |
|---|---|
| テーブル（`tbldefs/*.xml`） | EF Core エンティティ + Fluent 設定 |
| リレーション（`relations/`） | ナビゲーションプロパティ + FK 制約 |
| 選択クエリ（`queries/*.sql`） | LINQ。複雑なものはまず生 SQL のまま移し、後で分解する |
| アクションクエリ（UPDATE / INSERT / DELETE） | サービス層メソッド。トランザクション境界はここで引く |
| フォーム（`.form`） | 画面層。**UI フレームワークは利用側が決める**（この skill は決めない） |
| code-behind / 標準モジュール（`.cls` / `.bas`） | サービス層またはイベントハンドラ |
| 埋め込みマクロ / `macros/*.macro` | サービス層メソッド。宣言的な操作なので先に意図を文章化してから移す |

## 2. そのまま移せないもの

Access 固有の要素は 1:1 で置き換わりません。それぞれ何に置き換えるかと、なぜ 1:1 にならないかを整理します。

| Access 固有 | 扱い |
|---|---|
| `DoCmd.*` | UI 操作の命令。画面遷移はルーティング、レコード操作はサービス層呼び出しに分解する |
| `TempVars` | プロセス内グローバル変数。セッション状態やスコープの明確な DI に置き換える |
| `Forms!frmX!ctlY` のような画面参照 | 画面間の暗黙結合。ViewModel やイベント経由の明示的な受け渡しにする |
| `DLookup` / `DSum` / `DCount` 系 | インラインの集計・検索。LINQ のクエリまたはリポジトリメソッドに展開する |
| `Nz` | Null 合体。C# の `??` または `is null` チェックに置き換える |
| `IIf` | 三項演算子ではなく両方の分岐を評価する点に注意。C# の `?:` に移すときは副作用の有無を確認する |
| `CurrentDb` / DAO Recordset | 直接の DB ハンドル。EF Core の `DbContext` / リポジトリに置き換える |
| Access SQL 方言（`*` ワイルドカード、`#日付#` リテラル、`TRANSFORM`/`PIVOT`、`[Forms]![...]` パラメータ） | 標準 SQL や LINQ に書き直す必要がある。`.sql` をそのまま流用できない箇所を明記する |

## 3. 成果物テンプレ

生成先は利用側プロジェクト。見出し構成の目安は次の通り。

- `inventory.md` — オブジェクト種別ごとの件数・名前・一言説明・移植要否
- `dependencies.md` — 依存グラフ（フォーム → クエリ → テーブル、VBA → 関数の呼び出し関係）
- `csharp-mapping.md` — 1 オブジェクト 1 行の対応表 + 未決事項
- `diff-test-plan.md` — 旧システムと新システムに同じ入力を与えたとき同じ出力が出ることを確かめる差分テストの計画

## 4. 進め方

1. 棚卸し（`inventory.md`）
2. 依存グラフ（`dependencies.md`）
3. 対応表（`csharp-mapping.md`）
4. 差分テスト計画（`diff-test-plan.md`）

データの実際の値を確認する必要があるときだけ、read-only の SQL 実行（`vcs_execute_sql` など）を使います。
import / rebuild / RunVBA のような書き込み系ツールはこの skill の範囲では使いません。

## 5. 禁止事項

実データ・接続情報・特定の企業名やシステム名を成果物にそのまま貼らないでください。
サンプル値や識別子はダミーに置き換えてから記載します。
